\section{Data Extrction}
\label{sec:ch5.section1}

The starting point for the pipeline is the collected data. All data to be used for this investigation is a rosbag (.bag) or in the proprietary Livox file type (.lvx). The raw data has to be extracted from these file types before it can be processed or used in analysis. The Livox ROS driver includes functionality to convert .lvx files to .bag files. The file conversion retains all the point cloud data but does not save the IMU data to the created .bag file. MATLAB's ROS Toolbox contains functions that can extract data fields from a .bag file and convert each field to a standard MATLAB matrix or structure.

MATLAB's Lidar Toolbox has provision for a pointCloud object which was used for all data processing. This object contains fields for the point cloud's x, y and z co-ordinate data, point colours, normals and intensities. The Avia is only capable of directly measuring point intensity, so this was the only additional field extracted from the .bag files into MATLAB.

\section{Motion Compensation}
\label{sec:ch5.section2}

Two Kalman filters were created to estimate the attitude of the Avia during data collection. The filters output estimates of the sensor's roll and pitch (yaw cannot be reliably estimated from IMU data). Using these angle estimates an inverse transform can be applied to the point cloud to 'stabilise' the data and compensate for the motion of the observation platform (ship). As this Kalman filter only estimates changes in roll and pitch attitude, and not position, there will still be motion artefacts in the data due to translation and yaw of the observation platform. 

The first Kalman filter was created using MATLAB's Sensor Fusion Toolbox. The second Kalman filter is an Extended Kalman Filter (EKF) which was initially developed by Phil Salmony (cite here).

\section{De-Noising}
\label{sec:ch5.section3}


De-noise - the Avia not only records the location of each point, it also records how much of the original pulse of light is reflected back at the sensor (return intensity). This information is stored as an 8-bit value (0-255) attached to each point. With these data available, a simple threshold filtering function can be constructed. This function is useful for de-noising data collected under snowy conditions. When the Avia collects data in adverse environmental conditions (such as rain, snow, and fog), the beam emitted by the sensor may interact with these weather conditions, leading to poor quality data and/or noisy data. In the case of data collected from the SCALE Winter 2022 Cruise, snowy conditions resulted in unwanted returns from snowflakes in the area immediately in front of the sensor's minimum detection range. These unwanted returns create difficulties when trying to process the data further. The threshold de-noising function performs well in removing these unwanted returns and improving the usability of the collected data.

\section{Surface Estimation}
\label{sec:ch5.section4}


RANdom SAmple Consensus (RANSAC) plane fitting - RANdom SAmple Consensus is an algorithm that estimates a mathematical model from an input dataset. This method can be implemented to fit models of wave functions (sinusoidal and Stokes) to the collected data in an attempt to estimate the wave function parameters. The RANSAC algorithm estimates the model parameters by first selecting a random set of points in the dataset, either user-specified or the minimum number of points required to satisfy the model, and fits the model to these points. Using a user-selected tolerance, the algorithm then determines how many data points are inliers. This process is repeated until there are a satisfactory number of inlines or until the maximum number of iterations have been reached.

\section{Normal Estimation}
\label{sec:ch5.section5}


normal estimation - Using the point cloud data alone, the gross morphology of a pancake can potentially be estimated, but not much information about the surface conditions of the pancake can be inferred. Additional data on the geometry of the scanned pancaked would allow for further analysis of the pancakes and improved modelling. By estimating the normal of each point in the point cloud, it may be possible to estimate the surface conditions of the pancakes. Estimated normals may be able to identify features such as ridges, valleys, corners, concave, and convex shapes on the surface of individual pancakes. Normals are estimated by using \textit{k} number of neighbouring points to infer the geometry surrounding the subject point. First, the centroid of the subject point and its neighbour points is determined, and then the covariance matrix for each point is determined. A plane is then fit to have the least variance through all the points, and finally the normal to the plane is calculated.

\section{Clustering}
\label{sec:ch5.section6}


clustering - talk through why some clustering will  or won't work, k-tree stuff needs to know how many clusters there are, hierarchies don't make sense, DBScan relies on constant density (not ideal), optics needs an explanation. 
To identify the size and shape of individual pancakes, a method to associate individual points with individual pancakes is required. A method to achieve this is the use of a clustering algorithm. One such clustering algorithm is Density-Based Spatial Clustering of Applications with Noise (DBScan). DBScan identifies clusters in data based on how densely packed points are, clusters are dense regions separated by lower density areas (outliers). The function has a minimum of two input criteria; minPts, the minimum number of points required to form a cluster, and epsilon ($\epsilon$), the maximum distance allowed between points for them to be classified as being in the same neighbourhood. These parameters are used to classify points into one of three categories; core points, border points, and noise points. A core point is a point that has sufficient points, including itself (set by minPts) within a given radius (set by $\epsilon$). A border point is a point that is not a core point but is still within the neighbourhood radius ($\epsilon$) of a core point. A noise point is neither a core point nor a border point. Core points and their associated border points form an individual cluster, whereas noise points are not part of any cluster.

To group points into clusters it is necessary to determine which points are directly density-reachable, density-reachable, and density-connected. The point \textit{p} is directly density-reachable from point \textit{q}, if \textit{q} is a core point and \textit{p} is within the $\epsilon$ neighbourhood of \textit{q} (The distance between \textit{q} and \textit{p} is less than $\epsilon$). This property is symmetric for two core points, but not symmetric if one point (point \textit{p} in this example) is a border point.\\
The point \textit{p} is density-reachable from point \textit{q} if there is a chain of points p$_{1}$, ..., p$_{n}$ where p$_{1}$ = \textit{q} and p$_{n}$ = \textit{p} such that each point is directly density-reachable from the previous point in the chain. Similarly to direct density-reachability, this property is symmetric only for core points.\\
Points \textit{p} and \textit{q} are density-connected if there is a third point, \textit{o}, which both \textit{p} and \textit{q} are density-reachable from. This property is symmetrical for border points.\\ 
The DBScan algorithm iterates through all points, calculating distances between each other and categorising them as core, border, or noise points. An unassigned core point is the start of a new cluster. All neighbouring core or border points are assigned to this cluster
